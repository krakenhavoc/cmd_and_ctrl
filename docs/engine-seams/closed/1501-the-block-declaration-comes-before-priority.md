**The block declaration comes before priority, and a finished declaration is finished** (#1501, CR 509.1 / 509.1h / 117.3a, [ADR 0045 amendment 2026-10-03 (#1501)](decisions/0045-combat-restrictions.md) Decisions 68-70) — the two sandbox allowances #1279 kept on purpose. A block from a defender whose declaration is complete is refused with the new `illegal_block` reason **`blocks_declared`**, checked last so a block that is illegal anyway still names its own reason, so a ninja that entered attacking after the declaration cannot be blocked: an engine fact, not a table convention. And the declare-blockers step no longer hands the active player priority on entry: while any defender is still declaring, priority is **parked** (`priority_holder = -1`, `beginBlockDeclarationLocked`), the priority-gated verbs are refused for every seated player, and the last `finish_blocks` hands the active player the post-block window. A defender with nothing to block with is never waited on; one who concedes, the step being advanced, or a sandbox verb that empties combat (the dispatcher's `SettleBlockDeclaration`) all unpark it. `finish_blocks` is a new legal-move kind, AlwaysLegal, so a bot defender whose policy wants no block still finishes rather than holding the table; the heuristic prices it as the pass it stands in for. The client's dock line names the defenders the table is waiting on. Completion by `pass_priority` and the bot's block grace remain for the one shape in which a declaring defender holds priority (a restore point from before this change, or a player who became a defending player mid-step).
