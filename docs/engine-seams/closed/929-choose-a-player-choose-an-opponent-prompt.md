**Choose-a-player / choose-an-opponent prompt** (#929, [ADR 0018 amendment 2026-09-18](decisions/0018-triggers-on-the-stack.md)) — `Game.QueueChoosePlayerForEffect(ChoosePlayerPrompt{Chooser, Among, Source, Question, Item, Then})` (`game/choose_player.go`) and the card-facing `effects.ChoosePlayer{Chooser, Among, Except, Question, Then}` (`cards/effects/choose_player.go`), with `Among` one of `Players`, `Opponents` or `OpponentsOf(id)`. **No new prompt kind**: it is a `PendingChoiceOptionPick` with one option per eligible seat, labelled with that seat's name, so the choice gate, `legal.choiceMoves`, the wire projection and the client modal all answer it unchanged. It is the one Options-bearing prompt with nothing to hide — who is seated is public (CR 400.2) — so `redactChoiceCards` drops nothing and every viewer sees the same list. **The answer rides `StackItem.Payload`** as a `TargetPlayer` ref (#636's field, not a second one; `Targets` was not an option because a `pick_target` answer replaces it wholesale). A clause that asks twice appends twice in ask order: `ctx.ChosenPlayers()` is the exclusion list behind "choose a SECOND player" and `ctx.ChosenPlayer()` is the most recent answer, with a `TargetNone` marker recorded when a question could not be asked so a later clause never reads the earlier clause's player. **Eligibility is CR 800.4a** — a seat that has left is never offered — and the remaining seats are offered most-life-first, which IS the bot policy (the first option is the enumerator's always-legal one; see `docs/bot.md`). A prompt whose chooser is already gone when the question would be asked is simply not queued and the absence is recorded; reassigning one whose chooser leaves AFTER it is queued is `reassignChoiceLocked` (`game/pending_choice.go`), the CR 800.4g/h/i function that landed with the CR 800.4 remainder in #959. **4 cards converted:** Gluntch, the Bestower (new — three exclusive choices in one trigger, with the chosen player's own pick of a creature chained off the first); Skullwinder (new — the controller names an opponent and that opponent then picks from their own graveyard, which also takes it off the pick-from-graveyard row); Slithermuse (from an auto-pick to a real prompt, caveat cleared, now `CompletenessFull`); Fact or Fiction (the controller now names the opponent who separates the piles, clearing the caveat the row above carried, also `CompletenessFull`). **The as-enters half landed in #980** — see the row below; True-Name Nemesis is no longer waiting on anything. Sandstone Oracle (#448) is unblocked by it too — #952's re-triage moved it off the closed #744 and onto this row, and the row closed underneath it. Victory Chimes now needs exactly one thing, and it is not this: a mana ability whose mana goes to a player other than its controller (a mana ability resolves with no stack and no prompt, CR 605.3b, and `ManaAbilityShape` has no recipient) — its "untap during each other player's untap step" half has been expressible since #74 shipped `Spec.UntapStep`.
