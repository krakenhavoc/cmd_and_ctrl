**A spell copying itself at resolution** (#920, [ADR 0043 amendment 2026-09-18](decisions/0043-copy-effects.md)) — `resolveTopOfStackLocked` removes an item's `StackMeta` entry before it calls `OnResolve`, which is right as far as the STACK is concerned, and left `CopySpellForEffect` — which finds its source through that map — with nothing to copy when the resolving spell was the source. CR 707.10 allows exactly that ("that player may copy this spell"), and the whole Chain cycle prints it. **One slot, `Game.resolving`** (`game/resolving_item.go`), holding the `*StackItem` and a VALUE copy of the card the stack held: by the time the copy is actually made neither is otherwise reachable, because the copy decision is a PROMPT and the spell has already been routed to its owner's graveyard while it is open. The copy is therefore built from last-known information — in the rules the spell is still on the stack, since CR 608.2n puts it in the graveyard as the final step of its own resolution. **Lifetime is one event batch:** the slot is set when an item begins to resolve and cleared by `beginEventBatchLocked`, which runs at exactly the two points where play moves on (#829) — the next resolution and the cursor entering a step. That is what makes it survive any number of paused continuations belonging to the resolution that opened it and not one event past it, and it is safe because a resolution-time prompt blocks the table, so neither boundary can be crossed while a copy decision is open. `stackSpellLocked` consults the slot only for the resolving item's OWN id, so Reverberate pointed at a spell countered in response still gets `ErrCardNotFound`. Clone carries it (undo across the prompt); the persisted snapshot drops it and the drift plan says why, the `enteringTokens` precedent. **2 cards converted:** Chain of Vapor (`CompletenessFull` — the bounced permanent's controller is asked, the sacrifice gates the copy, and the copy is theirs per CR 707.10b) and Chain of Smog (caveat: the two cards discarded are random, which is `DiscardCards` everywhere and not this card's doing). Still open and NOT closed by this: copying an ABILITY item (Strionic Resonator, the ability-copy row above) is a different shape — an ability item carries a resolution closure rather than a card — and the slot parks ability items only so "the item currently resolving" has one answer.
