**An announced X paid by exiling artifacts of that total mana value** (#5401, [ADR 0020](decisions/0020-activated-abilities.md)'s 2026-10-03 amendment, the variable count it left out of scope; CR 601.2b, 601.2c, 601.2h, 602.2b, 202.3e, 608.2b) — Fabrication Foundry's "Exile one or more other artifacts you control with total mana value X: Return target artifact card with mana value X or less from your graveyard to the battlefield." The cost has no {X} symbol: X is the variable the exile defines, so it is announced with the activation (CR 601.2b, applied by CR 602.2b), the target is chosen against it (CR 601.2c), and the payment at CR 601.2h must add up to exactly that X. `game.ExilePermanentsCost.TotalManaValueX` (built with `effects.ExileArtifactsWithTotalManaValueX`: an open count of one or more, "other" as `ExcludeSource`) makes `AbilityCost.DemandsX` true, and `ActivateCatalogAbility` refuses, with nothing paid, a set of `exile_permanent_ids` whose total (`Game.ExileTotalManaValueForEffect`; a permanent's {X} is zero, CR 202.3e) is not the announced `x_value`, so no set of artifacts totalling X is no activation for that X (CR 118.3). The target clause is the existing `WithManaValueAtMostX` bound, bound at announce and re-checked at resolution (CR 608.2b). `effects.Register` refuses the form on a mana ability or a cast's additional cost, without an open count, and beside any other claimant on the announced X. The enumerator offers one payment per total the artifacts reach (`Game.ExileTotalManaValuePaymentsForEffect`, a subset-sum walk in payment order) and pairs each target only with the smallest total that admits it. The wire is additive: `exile_permanent_total_mana_value_x` on the ability row (public), no new `activate_ability` field; the client sends the picked artifacts' total as `x_value` and narrows the target picker by it, and the row's `cant_activate` says so when there is nothing to exile. No snapshot change. **Card:** Fabrication Foundry (Full).
