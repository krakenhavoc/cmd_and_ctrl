**Activation cost variants: a shared-colour reveal, sacrifice all of a kind, untap an opponent's land** (#6208, CR 602.2b, CR 118.3) — three activation-cost clauses that no component could express, each shipped as DATA on the component that already carried its sibling, so the ADR 0041 closure ratchet gains no route. **"Reveal two cards from your hand that share a color"** (Illuminated Folio) is `RevealCardsCost.SharesColor` (`effects.RevealNSharingAColor(n, label)`): a relation among the picks rather than a quality of one, judged pairwise as `TapOthersCost.SharesCreatureType` is, with a colourless card sharing none (CR 105.2c, CR 202.2). The option walk drops a candidate no other candidate shares a colour with (`revealWithColorPartnerLocked`), the validator checks the named set and refuses it with `ErrRevealedColorMismatch`, and `RevealCardsPaymentForEffect` is the enumerator's one payment, since the first two of the walk need not share a colour with each other. Revealing still moves nothing (CR 701.20b). **"Sacrifice all lands you control"** (Tomb of Urami) is `AbilityCost.SacrificeAll` (`effects.SacrificeAllYouControl(label, preds…)`), `AdditionalCost.SacrificeAll` (#2097) one cost site over: the `SacrificeOther` clause says which permanents and carries the "any number" bounds, the flag says the number is all of them, and `ActivateCatalogAbility` fixes the set through the cast path's own `sacrificeAllPaymentLocked` before the validator, the CR 903.9 walk or the payment reads `sacrifice_ids` (empty, or exactly the set, is a legal announcement). The source goes with the rest when the clause matches it, a phased-out permanent does not (CR 702.26b), an indestructible one does (CR 701.21a), and an empty board pays the cost in full (CR 118.3). The auto-tapper treats the set as sacrifice-named rather than untouchable, so a land may tap for the {2}{B}{B} and then be sacrificed (CR 601.2g before CR 601.2h). The enumerator names the engine's set on its one move, so the heuristic's `sacrificeCost` charges every land its board value and no gate of its own is needed. **"Untap a tapped land an opponent controls"** (Benthic Explorers) is `TapOthersCost.OpponentControls` (`effects.UntapTappedAnOpponentControls(n, label, preds…)`), the #5669 untap form with the owner turned over: one `tapOthersControllerOKLocked` decides the clause's owner for the option walk and the validator, so "you control" and "an opponent controls" are both the engine's own clause and neither can be reached by a card file that forgot a predicate. Untapping to pay does not target, so their hexproof land pays; only a tapped one does (CR 701.26b); one that can't become untapped does not (CR 614.17b); and a stun counter comes off in place of the untap with the cost still paid (CR 122.1d, CR 118.11). It is the first untap cost allowed on a MANA ability, which `ActivateManaAbility` now pays through the same untap payer — the activator never controls the permanent, so the CR 601.2h "source pays both components" ordering the CR 602 path needs never arises there, and the plain "you control" form stays refused on a mana ability. What the payment untapped is on the new `PaidCost.UntappedOthers []ObjectRef` (additive within the snapshot version, written before the untap because the epoch is a fact about the object on the battlefield, CR 400.7), which is how "one mana of any type that land could produce" reads the land through `ProducibleManaLocked` (CR 106.7). **The wire** gains one field and one flag, both additive: `mana_abilities[i].tap_others_untap` (the activated row already shipped it, so the client's picker now says "Untap" for Benthic Explorers), and `activated_abilities[i].sacrifice_options.all` with min = max = the count, so Tomb of Urami's picker confirms instead of asking (`sacrificeRangeShortfall` never greys an "all" row, since an empty board pays it). The shared-colour reveal needs none: the narrowing lives in the options walk, as `SharesCreatureType`'s does, and the validator refuses the pair the picker cannot grey. **Cards:** none in this PR — Illuminated Folio (OLD b537), Tomb of Urami (OLD b593) and Benthic Explorers (OLD b815) are built by their own OLD batches.
