**Paying {S} only with mana from a snow source** (#5986, CR 107.4h, 118.7b, 118.7g, 205.4g) — `{S}` in a mana cost or an activation cost parsed but was paid as `{C}`: a Sol Ring paid it and a Snow-Covered Forest did not. A snow slot (`ColorRequirement.Snow`) is now paid by one mana of any type whose token carries `ManaSourceSnow` (#1212's snapshot of the producing permanent, taken when the mana is made), and by nothing else. Every solver asks `ColorRequirement.PaidBy(color, snow)`: the pool solver's coloured pass (`colourRun.snow`, and the augmenting path tells an `{S}` from a `{C}`), the auto-tapper's slots (`tapSource.Snow`, own slots only; trigger mana is planned as nonsnow), the costed planner's floating sources and the pool top-up, which credits only snow mana to an `{S}` and spends nonsnow mana on a coloured symbol first. So the payment, the auto-tap preview, the greyed actions and the legal-move list agree. The executor's colour ledger leaves snow slots out. A generic reduction never reaches an `{S}`, a reduction by `{C}` is generic instead (`takeRequirement`), no "spend as though any color / type" grant widens it, convoke cannot pay it, and a paper declaration for a shortfall with an `{S}` is snow mana. Snapshot: no new field. **Cards:** Hailstorm Valkyrie, Grim Draugr, Chilling Shade, Frost Raptor and Boreal Griffin (all `full`). **Still open:** reading "{S} spent to cast this spell" (Blessing of Frost, Graven Lore, Tundra Fumarole), which `ManaSpent.CountFrom(ManaSourceSnow)` can answer once a card declares it.
