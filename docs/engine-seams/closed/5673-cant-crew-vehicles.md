**Can't crew Vehicles** (#5673, CR 702.122d / 602.5; part of #5493) — "enchanted permanent can't … crew Vehicles" is the first bit of a second restriction set, `game.ExtraRestriction` (`game.CantCrew`, wire token `cant_crew`), because `game.Restriction` is a `uint8` whose eight bits are taken and is on disk, so widening it would be a snapshot retype. The new set rides beside the old one as additive omitempty fields (`Characteristic.ExtraRestrictions`, `Mod.ExtraRestrictions`), so old snapshots load unchanged; it is written by `RestrictAttachedExtra` / `RestrictSelfExtra` and `RestrictUntilEOT`'s `ExtraRestrictions`, carried by a scoped record through a restore like the other bits, and its tokens follow the first set's on `CardView.restrictions`. CR 702.122d makes it a rule about one payment ("that creature can't be tapped to pay the crew cost of a Vehicle"), so the one predicate `game.CanCrewVehicles` is read where a crew cost picks its creatures and nowhere else: `validateCrewCostLocked` refuses a payment naming such a creature with `game.ErrCantCrew` and taps nothing, the view leaves it out of the crew row's `crew_options` and `crew_power` (the client's picker reads only those), and the enumerator's `crewPayment` skips it, so a bot is never offered the move. A saddle cost (CR 702.171a) and a teamwork cost run the same walks and still take the creature. The tile label words the set as printed ("Can't attack, block, or crew Vehicles."). The next restriction bit goes in `game.ExtraRestriction` too. **Cards:** Intercessor's Arrest (Full).
