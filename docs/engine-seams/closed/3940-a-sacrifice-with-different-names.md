**A sacrifice with different names** (#3940, [ADR 0020 amendment 2026-10-16](decisions/0020-activated-abilities.md)) — the last half of the `set-level-sacrifice-cost` row: a rule over an ATTRIBUTE of the picks, Transmutation Font's "{3}, {T}, Sacrifice three artifact tokens with different names". #2526's `EachOf` matches picks to printed kinds and could not say it. The target clause's set rule could: `TargetSpec.Different` (#1559) now rides a sacrifice clause, built with `effects.SacrificeNDifferent(n, label, EachDifferentName(), preds…)`, and adds no route from Game to a func because the field already hangs off `TargetSpec`. `validateSacrificeCostLocked` refuses two picks that share a key, naming the rule. `legal.sacrificePayments` takes one payment from `game.SacrificeDifferentPaymentForEffect`, the first permanent of each key in payment order, instead of "the first N". The view ships each option's key as `sacrifice_options.different`, and `SacrificeCostModal` greys an option whose name is already picked, holds Confirm until the picks differ, and its "Choose for me" takes the first of each name. A cost reads the rule strictly (CR 201.2b: objects have different names only if each has a name), so a nameless permanent is no candidate. `effects.Register` allows the rule on an activated ability's sacrifice clause only, at a fixed count of two or more and not beside `EachOf`. **Transmutation Font** ships `full`.
