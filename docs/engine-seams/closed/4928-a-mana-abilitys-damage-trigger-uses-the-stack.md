**A mana ability's damage trigger uses the stack** (#4928, CR 605.1b / 605.3b / 603.3 / 603.12, [ADR 0011](decisions/0011-mana-pool-and-auto-tapper.md) amendment) — Zhur-Taa Druid's "Whenever you tap this creature for mana, it deals 1 damage to each opponent" was declared as a rider inside the mana ability, so nobody could respond to the damage or counter it. CR 605.1b makes a triggered ability a mana ability only if it could add mana, so this is an ordinary trigger. `effects.ManaAbility.PingOpponentsTrigger` now grows a catalog `Triggered` row that watches `EventManaAbilityActivated` for that row (its source, label and activator). An attack, a crew or an opponent's tap effect doesn't fire it. The row is stamped like any other (ADR 0041 P9), so a table with the damage waiting restores. The mana still lands at once (CR 605.3b). `ActivateManaAbility` now runs its exit boundary whenever the activation queued a trigger, so the trigger reaches the stack while the activator holds priority (CR 603.3). The boundary still holds while a resolution is open. The planner reads `ManaAbilityShape.TriggerOpponentDamage` and keeps the source in the table tier (#4189). Painlands, Talismans and Grove of the Burnwillows keep their riders, because that damage or life gain is part of the ability's own effect. **Cards:** Zhur-Taa Druid (Full). Rubble Rouser's reflexive "When you do" (CR 603.12) takes the same declaration when #4927 lands.
