**Three resolution-time prompt kinds** (#1214, CR 608.2 / CR 701.20, [ADR 0018 amendment 2026-09-22](decisions/0018-triggers-on-the-stack.md), [ADR 0060 amendment 2026-09-22](decisions/0060-leaving-the-game.md)) — three rows closed together because they were one shape: a decision a card asks for *while it is resolving*, answered by a named seat, with the rest of the card hanging off the answer. **`reveal_pick`** — an opponent picks from a set you revealed (Gifts Ungiven, Intuition; a pile split's first leg is now this kind, which is what it always was). **`their_permanents`** — a seat choosing among the permanents somebody ELSE controls (Tragic Arrogance), the direction the sacrifice run cannot face, since `PendingChoiceSacrifice` is queued `{Chooser: p, FromPlayer: p}` at its one queue site. **`own_permanents`** — "choose N of your own permanents" at resolution, untargeted (Scapeshift's "sacrifice any number of lands"), which the fixed-count sacrifice prompt could not say and could not be read for a total. **ONE PAYLOAD:** all three carry the choose-cards fields and a `chooseCardsFrame`, so `isCardSetPickKind` admits them and `checkChooseCardsPicksLocked` (bounds, candidates, duplicates, the live-zone re-check, #1017's set-level `Validate`), `ChooseCardsPickLegalLocked`, `setCardSetCandidates` and both prunes are written once; `reassignChoiceLocked`'s candidate prune became one `isCardSetPickKind` arm in the same pass. **THREE KINDS** because each difference is observable: what a non-chooser may see (a reveal is PUBLIC, where `filterPendingChoices` withholds even a `choose_cards` prompt's bounds), which way a bot should read the answer (#1014's `OrderTargets` for the two that rank somebody else's material, `OrderCostFuel` for the one that spends the seat's own), and who inherits it under CR 800.4g. **ONE CONTINUATION:** every one is a RUN (`runPromptsLocked`, #1019 / #1027), so Tragic Arrogance's one printed instruction asked as one prompt per player settles once — and `dropDefault` reaches `settleRunLegLocked` through `PendingChoice.promptRun`, the branch `defaultDroppedChoiceLocked` already took on the run link rather than on the kind, so the three kinds needed no new code in the departure sweep, the performer or either gate. It also fixed a hole one leg upstream of #1006: a Fact or Fiction splitter who left AFTER the question went up hit a `dropDefault` that found no run and no option frame, ran nothing, and put neither pile anywhere. **Cards:** Intuition, Gifts Ungiven, Scapeshift and Tragic Arrogance all ship `full`; Fact or Fiction moved onto the shared first leg unchanged. **Still open and a second axis rather than a deeper version of this one:** The Legend of Yangchen's chapter I (#343) needs several players choosing from ONE SHARED POOL with each answer narrowing the next, and Gluntch, the Bestower (#391) needs two target players before the pick and a different effect per seat. Neither is blocked on a prompt kind any more; both are card work plus a sequencing shape, and they keep their own notes on their batch issues.
