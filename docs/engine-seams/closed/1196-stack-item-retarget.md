**Stack-item retarget** (#1196, CR 115.7, [ADR 0019 amendment 2026-09-22](decisions/0019-structured-targeting.md)) — rewriting the targets of a spell or ability that is already on the stack. The row the 2026-09-16 audit singled out as undercounted, and the whole of it is one observation: **retargeting is the announce gate run a second time, for a different chooser.** `Game.RetargetStackItemForEffect(itemID, chooser, policy, next)` takes the WHOLE new target list, one-for-one with the item's current one, and re-runs `validateAnnouncedTargetsLocked` over it with the item's own announced clause list and its own `TargetSource` — so per-clause predicates, zones, `Min`/`Max`, `AllowSame`, `Distinct` and `CanBeTargetedBy` (protection, hexproof, shroud) are all enforced without being restated — including, since #1197 landed a day earlier, the PLAYER half of that gate, so a seat with hexproof is not among the alternatives offered for an opponent's spell and a seat with protection from red is not among a red spell's, with no line of this seam's own. Three rules are the retarget's own: **one-for-one** (CR 115.7 changes which objects are targeted, never how many, and never which clause a slot answers), a **change count** (`RetargetChangeOne` for "change the target", `RetargetChooseNew` for "choose new targets"), and an **unchanged slot's predicate is waived** — CR 115.7c lets a player leave a target alone even if it is now illegal, which is the one new parameter on the announce walk (`validateAnnouncedTargetsWithLocked`'s `waive`). **The chooser is not the controller**: legality is judged from the ITEM's point of view (its controller, its own card as the protection source) while the prompt goes to the retargeting effect's controller, so a Swat on an opponent's "target creature you control" can only move it to a creature THAT OPPONENT controls. `PaidCost`, modes, X, `AltCost` and `CastFromZone` are untouched; `Distribution` is REMAPPED positionally, because it is keyed by target id and CR 115.7c says the division can't be changed. **`PendingChoiceRetarget`** is a prompt kind of its own rather than another `pick_target`, and the departure table is why: `pick_target` is `{reassign: true}` and nobody else aims another player's Deflecting Swat, so `retarget` is `{}` — dropped, targets unchanged. It carries DATA, not a continuation (the object it rewrites is already on the stack), so a game paused on one is a restorable snapshot, which is true of no other prompt in this family. The wire and the client picker reuse `pick_target`'s projection unchanged; `internal/legal` gets its own case, ordered through #1014's `OrderTargets` and offering the decline when `min` is 0. **CR 707.10c moves onto the same check**: `spell_copy.go`'s re-target validated with the ANNOUNCE gate, which refused a target the player left alone that had since become illegal and allowed the count to change — both wrong for a copy, and both now the shared `retargetCheckLocked`. **4 cards:** Deflecting Swat (#294) and Bolt Bend ship `caveats` for the "or ability" half; Misdirection and Imp's Mischief (#298) ship `full`, since both print "target spell". **Still open, and each a different shape**: ~~targeting an ABILITY on the stack~~ — **closed by #1211**, which made Deflecting Swat and Bolt Bend `full` by widening their clause and needed no line of retarget code, because this entry point was written over `StackMeta` from the start; a multi-slot "change *a* target", which would have to ask which slot first and has no printed card; and **Spellskite** (#302), which changes a target TO a named object rather than offering a choice, and does it from an activated ability with a Phyrexian mana cost.
