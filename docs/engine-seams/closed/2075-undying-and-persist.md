**Undying and persist** (#2075, CR 702.93 / 702.79, [ADR 0113 §4](decisions/0113-small-seams-for-the-s58-deck-requests.md#4-undying-and-persist-2075)) — the first dies keywords derived from the ability list. `undying` and `persist` join `canonicalKeywords`, both cumulative (CR 113.2c). The leaves-the-battlefield harvest used to read only catalog triggers and returned early for a permanent with no catalog key; `harvestLTB` now asks `ltbKeywordTriggersFor` for one trigger per token on the departed permanent's LAST-KNOWN ability list first (CR 603.10a), so a printed instance (stamped by the deck importer), a token's and a layer-6 grant all work with no catalog entry, and a creature that died having lost all abilities has none. The intervening "if" (CR 603.4) reads the counters it last had, as it dies (`lastKnownCounters`) and again on resolution (its `PermanentInfo`). The keyed bodies `undying/return` and `persist/return` return the card only while it is still the graveyard object the ability triggered with (CR 400.7e; the item's `SourceObject` is that object), under its owner's control (the trigger is the last controller's, CR 603.3a), with the counter on the entry event so a CR 614 counter replacement applies (CR 122.6). A token, or a card that left the graveyard, returns nothing and raises no error. **Also fixed:** the state-based actions ran the CR 704.5q +1/+1 / -1/-1 cancel before the destruction sweep, so a creature that died in the same check lost a counter it should have died with; the cancel now runs after the sweep (CR 704.3), which never changes power or toughness. Two new on-disk body keys and a v7 corpus board (`persist_trigger_pending.json`); no shape change. The bot values both tokens in its keyword table. **Cards:** Gleeful Arsonist and Persistent Constrictor, Full; Murderous Redcap drops its caveat and goes Full. The vanilla undying and persist creatures need no card file. **Still open:** the rest of the pool lands in follow-up card PRs.
