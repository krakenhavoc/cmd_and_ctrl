**Losing one of its own abilities** (#1859, CR 613.1f / 611.2a, [ADR 0107 amendment of 2026-10-07](decisions/0107-state-triggers-rebound-disturb-and-damage-prevention.md)) — a permanent could lose all its abilities or a keyword, but not one particular ability that is not a keyword. `loseOwnAbility` is a layer-6 mod naming a slot (`replacement`, `triggered`, `activated`) and a row of the object's own definition; it writes `Characteristic.RemovedOwnAbilities`, which the ability key (`catalogAbilityKeyOf`, `AbilityKeyFromLKI`) turns into a definition without that row, and `activatedAbilityRows` filters an activated row by index while keeping the survivors' refs. A later grant of the same text is a different row and survives, a copy and a flickered object still have the ability, and the record ends at cleanup, rides undo and the snapshot (additive), and takes the row off the view's ability chips. **Glittering Lion** and **Glittering Lynx** are new and `full` (`PreventAllDamageDealtTo` is the new plain-prevention constructor). **Still open:** removing one STATIC or MANA row, which no card waits on: a static is gathered by the layer pass before any effect applies and a mana row's ref numbers through the intrinsic land half (`loseOwnAbilityModProblem` refuses both slots, so none can ship unhonoured).
