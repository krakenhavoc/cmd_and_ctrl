## DONE

### #38 — Battlefield viewer-POV: rotate so controller's permanents sit on their side

The issue asked to choose between two designs: (1) controller-relative wire coordinates, or
(2) client-side rotation of an absolute battlefield rect inside `table.ts`. Neither was taken.
The S06 PixiJS table was deleted outright and replaced by a per-seat HTML/CSS panel layout, which
delivers the issue's actual goal — "your permanents should appear on your side of the table" —
structurally rather than geometrically.

Evidence, all on `6724349`:

- `client/src/lib/cardTypes.ts:92` — `seatPlacements(seats, viewerID)` resolves the viewer to the
  `self` slot unconditionally (`out.self = seats[selfIdx]` at :97), then fills the remaining seats
  clockwise into `next` / `across` / `across_next` (:99-110). Spectators fall back to seat order
  (:114-118), so a viewerless client still renders coherently.
- `client/src/lib/components/board/Board.svelte:123-131` — `cardsByController` buckets the single
  shared battlefield `ZoneView` by `c.controller`.
- `client/src/lib/components/board/Board.svelte:582` — each seat's panel receives
  `controlledCards={cardsByController.get(seat.id) ?? []}`, so a permanent renders on its
  controller's side, and follows a control change automatically.
- `client/src/lib/components/board/Board.svelte:565-573` — panels are placed by
  `style:grid-area={pos}` with `flipped={pos === "across" || pos === "across_next"}`;
  `PlayerPanel.svelte:387-400` implements `flipped` by reversing `grid-template-areas` (hand at the
  outer edge, creatures toward centre) rather than a 180° transform, so text stays upright.

Two bullets from the issue's task list are unmet, and both are artifacts of design 2, which was not
chosen: "handle tap orientation consistently" (tap is a uniform 90°, `animations.ts:83`) and the
per-viewer rendered-position regression test (`seatPlacements` has no unit test — there is no
`client/src/lib/cardTypes.test.ts`). Neither is a gap in the delivered behaviour; with per-seat
panels a uniform tap rotation is correct. Recommend closing, and filing the `seatPlacements` unit
test as a good-first-issue if it is wanted.

## OBSOLETE

### #40 — Table layout uses fixed pixel anchors — overlaps on canvases under ~720px tall

The issue describes the PixiJS canvas renderer, which no longer exists. `client/src/lib/table.ts`
and `card-tile.ts` are gone; only comments refer to them
(`Board.svelte:6-7` — "Replaces the entire PixiJS table renderer (client/src/lib/table.ts)").
The replacement is a CSS grid: `Board.svelte:711-717` (`display: grid; width: 100%; height: 100%;
overflow: hidden`), fr-based templates with `minmax(0, …)` at `:781-806`, `.slot { min-height: 0;
min-width: 0 }` at `:740-743`, and `PlayerPanel.svelte:349-367,405-421` mirroring the same guards.
The single absolutely-positioned element, the attention strip, uses
`min(512px, calc(50% - 132px))` (`Board.svelte:751-762`).

The overlap symptom the issue names cannot occur any more. One residual behaviour is worth a fresh
issue rather than keeping this one open: card height is still a fixed pixel value scaled only by a
user preference — `PlayerPanel.svelte:343-345`, `--card-h: calc(168px * var(--card-scale, 1))` —
and there are no height-based media queries anywhere in `client/src`. On a short viewport, content
now *clips* under `overflow: hidden` instead of overlapping. Recommend closing as obsolete and
filing "scale cards to viewport height" if that clipping matters.

## Where the tracker and the docs misrepresent the code

1. **`docs/decklists/aang-is-so-flashy.md:159-160`** says Sun Titan is blocked because the engine
   lacks graveyard recursion. It does not. `ReturnFromGraveyard{Dest: ...}` is a primitive at
   `server/internal/cards/effects/primitives.go:220-226`, backed by
