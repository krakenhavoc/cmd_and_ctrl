# Engine seams

A seam is an engine gap a card in the catalog (`server/internal/cards/effects`)
is waiting on: an event kind, a cost component, a prompt shape, or a
primitive that `server/internal/game` does not yet provide. A seam is not a
bug: bugs found by the roadmap sweep (issues #446, #478, #482, #489, #492)
are tracked and fixed on their own, separately from this list.

This file is the seam registry for the card-coverage roadmap (Discussion #559 item 6, issue #580). It replaces
the seam lists that used to live only in agent prompts and in scattered
batch-issue comments. The rule going forward: every batch PR appends its
own skipped cards to the table below, merging into an existing row when the
seam is the same one already listed, and a seam moves from Open to Closed
on the day the engine PR that closes it lands.

The table began as every seam reported against **two or more** waiting
cards in the first pass over the first 3600 cards (batches 01-36, issues
#294-#313 and #383-#399); the rows added from the 2026-09-16 audit (below)
reach batch #467, and a few of them start with fewer recorded skips. A seam that blocks exactly one card today is
noted on that card's own batch issue rather than duplicated here; it will
earn a row here the moment a second card waits on it.

**Count** is the number of cards that batch issues and batch PRs have
recorded as skipped for the seam: the cards named in the row plus its
"+N more" (on a row added from the audit, only the cards before "audit
adds:"). It changes only when a batch PR appends a skip or a skip
moves to the row it really belongs in, so it undercounts a seam that
other batches hit without writing the skip here.

**Audit** comes from the card-coverage audit of 2026-09-16, which
classified every gap card on the 60 batch issues (#294-#313, #383-#403,
#448-#467; 5,084 cards). It gives the number of cards where the seam is
the *only* core blocker, then the number where it is *any* core blocker.
It is a classifier's attribution, not a skip list, and it is never added
to Count. For each seam the verifiers sampled the only-blocker cards and
found between about 5% and 85% of them also blocked by something else or
misattributed, so read it as an upper bound. For a row tracked by one of #742-#765, that
issue has the verified estimate and the cards that were checked. A figure marked †
was not verified against the code. Rows outside the audit's top 40 seams
are left blank. The one exception the audit called out by name —
stack-item retarget, whose Count of 3 it flagged as an undercount — is
in Closed seams since #1196.

The rows from "Classes, Cases and Rooms" to the end of the table were
added from that audit (2026-09-17) — the run used to start one row
earlier, at "Transform a permanent / enter transformed", which has since
closed (#343) and moved below. Their Count is **—**
unless skips already recorded in this file moved into them (Station and
library-top cast), and their Cards waiting column lists cards the audit's
verifiers checked, each with its batch issue. They follow the same rule
as every other row: a batch PR appends its skips, and the row moves to
Closed when the engine PR lands.

- **Stack-item retarget** (#1196, CR 115.7, [ADR 0019 amendment 2026-09-22](decisions/0019-structured-targeting.md)) — rewriting the targets of a spell or ability that is already on the stack. The row the 2026-09-16 audit singled out as undercounted, and the whole of it is one observation: **retargeting is the announce gate run a second time, for a different chooser.** `Game.RetargetStackItemForEffect(itemID, chooser, policy, next)` takes the WHOLE new target list, one-for-one with the item's current one, and re-runs `validateAnnouncedTargetsLocked` over it with the item's own announced clause list and its own `TargetSource` — so per-clause predicates, zones, `Min`/`Max`, `AllowSame`, `Distinct` and `CanBeTargetedBy` (protection, hexproof, shroud) are all enforced without being restated — including, since #1197 landed a day earlier, the PLAYER half of that gate, so a seat with hexproof is not among the alternatives offered for an opponent's spell and a seat with protection from red is not among a red spell's, with no line of this seam's own. - **Attack taxes** (#1063, CR 508.1a, [ADR 0080](decisions/0080-attack-taxes.md)) — "creatures can't attack you unless their controller pays {2} for each creature they control that's attacking you". - **Transform a permanent** (#343 / #1112, CR 701.27, CR 712.18, [ADR 0079](decisions/0079-transforming-a-permanent.md)) — the verb, and it is deliberately **two** verbs. `Game.TransformPermanentForEffect` turns a battlefield permanent over IN PLACE and never goes near `MoveCard`: CR 712.18 says the permanent doesn't become a new object, so `InstanceID`, `ObjectEpoch`, counters, marked damage, tap state, attachments, the CR 613.7 timestamp, summoning sickness, the controller and every `Game`-side per-object registry all survive, and no `EventZoneMove` / `EventETB` / `EventLTB` is emitted — a back face's "when this enters" trigger does **not** fire off a transform, because nothing entered. `Game.ExileAndReturnTransformedForEffect` is the OTHER shape ("exile this Saga, then return it to the battlefield transformed", CR 712.14a): two zone changes, CR 400.7 in full, a genuinely new object. Conflating them gives Fable of the Mirror-Breaker a Saga that kept its lore counters and Storm the Vault a permanent that re-triggers its own ETBs — wrong in opposite directions, which is why they are two functions and not a flag. Card-side: `effects.Transform{Target}`, `effects.TransformThis{}`, `effects.ExileAndReturnTransformed{Target, Controller}`. **What made it small** is that ADR 0034 had already built the representation — `Card.Faces` / `ActiveFace` / `SetFace`, the `"<oracle_id>#1"` catalog key that hands the back face its whole `Spec` for free, `MoveCard`'s CR 712.8a reset, and `layout` / `faces[]` / `active_face` already on the wire, in `cardSnapshot` and in `cloneCard`. **No new `game.Card` field**: "this permanent is transformed" is `ActiveFace != 0`, which is how CR 701.27g reads and which was already on disk and already on every snapshot. **`EventTransform`** carries the permanent, its controller, the face it turned to and the name of the face it turned from; `layerVersionBump` gains an arm for it, which is not optional — a face change is a *printed-value* change and `Effective()` serves a warm cache, so without it a transformed Storm the Vault keeps reporting "Legendary Enchantment". `LogTransform` narrates it, per #984's gate. **CR 701.27c/d is `nil` and no event**, not an error and not `EventEffectError`: an instruction that legally does nothing is a resolution, not a card that threw, and the catalog soak fails a game on the latter. The layout allowlist in `CanTransform` is the load-bearing line — an `adventure` card also has two `Faces`. One rider came with it: **CR 712.8e**, a nonmodal back face's mana value is computed from its FRONT face's cost, which `ParsedManaValue` was getting wrong as 0 for every transformed permanent. **Transforming Sagas needed no change at all**: `IsSaga` reads the effective subtypes and `SagaFinalChapter` derives from the back face's (absent) chapter triggers, so CR 714.4 finds nothing to sacrifice whichever shape the card uses. **Cards:** Storm the Vault // Vault of Catlacan (`full`) and Fable of the Mirror-Breaker // Reflection of Kiki-Jiki (`caveats`); the four Avatar: The Last Airbender transforming Sagas (`#343` — The Legend of Kuruk // Avatar Kuruk, The Legend of Kyoshi // Avatar Kyoshi and The Legend of Roku // Avatar Roku, `caveats`, and The Legend of Yangchen // Avatar Yangchen, `caveats`), all using `ExileAndReturnTransformed` exactly as Fable does; and Aang, Swift Savior // Aang and La, Ocean's Fury (`caveats`), the first card to reach a back face through `TransformThis` on an ACTIVATED ability rather than a Saga's chapter III — its Waterbend {8} pays a flat mana cost instead of the printed discount, which is the tap-another-permanent seam below, not this one. - **A bot prices the cards a cost eats** (#1013, [ADR 0033 §1 amendment](decisions/0033-ai-bot-seat.md)): the enumerator offered exactly ONE payment for the card-shaped half of an alternative cost (`legal.maxEnumeratedCostPayments` was 1) and built it out of the first N candidates in ZONE order, so an escaping Uro over a graveyard holding a second Uro, a Snapcaster target and three lands ate whichever three were oldest.
