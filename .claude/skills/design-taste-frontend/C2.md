## Scope

Public, signed-out pages only: the front page, Roadmap, About and Guide. Never the
table, the lobby or the decks screens (the skill itself says it is not for app screens).
C2's own system is in `DESIGN.md`; read it first and treat it as the authority for
tokens, type and voice.

## C2 overrides

- No card art on the front-door pages (front page, request-access, Roadmap, About,
  Guide; `DESIGN.md` §9), and there is no photography. The public Catalog is the one
  signed-out page with card art, and an art crop shown as a card's main view carries the
  artist credit. The Roadmap publishes names and caveats only (ADR 0092). The skill's
  "real pictures" floor is met with interface fragments: real product UI whose root
  carries `data-ui`.
- Keep the brand's orange accent and its mono voice for counts. Where the inspector's
  `mono`, palette or similar rules flag those, pass `--allow <rule>` for that rule only
  (for example `--allow mono`) and say why in the report.
- `assets.mjs` is the only script that uses the network (open image collections); do not use it here.

## Running the inspector

`lint.mjs`, `inspect.mjs` and `draw.mjs` need Node 22+ and no dependencies. Run them
from a scratch directory, because `inspect.mjs` writes `.taste-skill/` into the current
directory (that name is ignored by the repository's ignore file).

On Ubuntu, AppArmor's unprivileged-userns rule kills Chromium's sandboxed launch, so
point `CHROME_PATH` at a wrapper that adds `--no-sandbox` around Playwright's Chromium
(`~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome`):

```sh
cat > /tmp/chrome-nosandbox <<'SH'
#!/bin/sh
exec "$(ls -d ~/.cache/ms-playwright/chromium-*/chrome-linux64/chrome | tail -1)" --no-sandbox "$@"
SH
chmod +x /tmp/chrome-nosandbox
mkdir -p /tmp/taste && cd /tmp/taste
CHROME_PATH=/tmp/chrome-nosandbox node <repo>/.claude/skills/design-taste-frontend/scripts/inspect.mjs http://localhost:5173/
```
