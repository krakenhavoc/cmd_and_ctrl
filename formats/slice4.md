Scope:
- A **draft** is its own lobby object, not a game: an id, a host, a set (only a set the draftable check passes), a pick mode, 2 to 8 seats. Design where it lives by reading how tables live in `server/internal/lobby` and how a table room broadcasts over `server/internal/ws`; reuse those patterns (auth, guests, invite link, the name filter, capacity) and do not fork them. "Pod" already means something else in this codebase (ADR 0220): never call a draft a pod.
- **Pick one**: each seat opens three packs in turn; after each pick the rest of the pack passes to the next seat, left in rounds one and three and right in round two (CR 905.1a and 905.1b on the pinned rules: quote them). **Pick two**: each pick takes two cards from the pack; offered by default at 4 seats and allowed at any size. Packs come from `draftpacks` with a seed kept on the draft so a draft can be replayed in a test.
- **Bots fill the seats.** Any seat no person has taken when the host starts is a bot. One person and seven bots is a normal draft. In this slice the bot is a placeholder behind an interface (`Picker`: given the pack, the seat picks so far and the pick mode, return the pick): it picks at random from the seeded source. Slice 5 (#5439) replaces it, so make the interface the only thing that slice has to implement.
- **A pick timer.** When it runs out the seat gets the placeholder picker choice for that pack. A person who disconnects is picked for the same way and can come back to their seat and their picks.
- **Hidden information.** A seat sees only the pack it is holding and its own picks (CR 905.1c: quote it). The server never sends another seat picks or pack. Give the draft a per-seat view the way the game has one, and a test that walks every message a seat receives and fails on a card it should not see.
- **When the last pick is made** the draft holds each seat pool and stops. Deckbuilding and the matches are slice 6 (#5440): expose the pools through a clear function and view, and leave a visible "deckbuilding comes next" state.
- **Client:** a create-draft form (set picker from `GET /draft/sets`, pick mode, seats), the draft lobby, and the pick screen: the current pack as cards, your picks so far grouped by colour and mana value, the timer, who is still picking. DESIGN.md first; labels from `client/src/lib/labels.ts`; card images and hover the way the table and deck pages already do them. A visitor can draft against bots with no sign-in, like a practice game today.
- **Limits and storage (ADR 0222 section 9, ADR 0148, ADR 0149):** a draft counts as one table against the capacity cap while people are picking; idle drafts close the way idle tables do (ADR 0211). In THIS slice keep a draft in memory only and store nothing about a person; say so in the PR. Persisting a finished draft is slice 6.
