# Planechase plane cards: brief for a cloud session (ADR 0216 slice 4, epic #4870)

You add plane cards to the cmd_and_ctrl catalog so a Planechase table's planar deck plays automatically instead of falling back to manual. Read docs/decisions/0216-planechase-as-a-table-option.md IN FULL first, especially §6 "How a plane's abilities register", §12 slice 4, and the slice 1 and slice 2 amendments (the planar die, `EventRollDie.PlanarFace`, chaos ensues, `planeswalkLocked`, `EventPlaneswalkTo`/`From`, `UntilPlaneswalkAway`). Slices 1–3 are on develop (#4963, #4965, #5352). The inherent planeswalking ability is engine-wide; never write it into a card.

## Where things are (this cloud session cannot reach Scryfall or wizards.com)
- This brief and the data live on branch `work/planes-cards` (never merge it, never PR it): `git fetch origin work/planes-cards`, then `git show origin/work/planes-cards:planes/batches/NN.json`. Each card has its oracle text, any related tokens, and its official rulings (follow them). Index: `planes/batches.txt`. Phenomena (`planes/phenomena.json`) are slice 5, NOT yours.
- Comprehensive Rules, pinned 2026-09-25 edition: `planes/cr.txt`. Rule 901 (Planechase), 311 (planes), 312 (phenomena), 706.7 (planar die). Grep and quote before citing any rule; never cite from memory.

## Setup
- `git fetch origin && git switch -c feat/planes-batch-<N> origin/develop`. Read AGENTS.md (binding: commit and PR format, closure ratchet, snapshots additive) and docs/adding-cards.md subsections you need.
- Go: `go` from server/ (install the version in server/go.mod if missing). One Go command at a time; never `go test ./...`.
- Before each card, check it isn't on origin/develop (grep its oracle_id) or in an open PR.

## Card rules
- One file per plane, `server/internal/cards/effects/<snake_name>.go`, one init(). Opt-in by oracle_id. Follow the registration shape ADR 0216 §6 and its amendments define; if batch 1 has landed, copy its pattern exactly (grep `planar` / an existing plane file).
- A plane's static and triggered abilities work only while it is face up in the command zone (CR 901.4 / 311.x); its "Whenever chaos ensues" ability triggers on a chaos roll (and on other "chaos ensues" effects). The controller of a plane's abilities is the planar controller (CR 901.6). Test both the static/triggered part and the chaos part with engine-driven tests on a Planechase table.
- Every card CompletenessFull, no caveats, never stamped falsely. Stronger or weaker than printed are both wrong. A clause the engine can't express: build it if additive and contained; if it needs protocol + client work or an owner decision, leave the card out and list it under `## Skipped` with the exact clause (the owner starts a seam worker).
- Merge-friendly: any new shared helper goes in a new file `planes_b<N>_helpers.go`; grep develop and open `feat/planes-batch-*` branches first and reuse.
- TestNoNewExactClonesInTheCatalog: extract a shared helper, never reshape to dodge it. Effect keys only via `go test ./internal/cards/effects -run TestEveryPersistedEffectKeyResolves -args -update-effect-keys`. Roadmap: `go test ./internal/roadmap/ -args -update -update-closed`. Declare fixed-amount riders via `Purpose` (TestRiderPurposesMatchThePrintedCard). One-sentence triggers use `effects.Do` primitives with a footprint (TestOneSentenceTriggersDeclareFootprints).
- **Batch 1 only:** adds the planar census line (ADR 0216 slice 4 says "The first batch adds the planar census line") and settles the registration pattern every later batch copies; document it in docs/adding-cards.md (a short "Plane cards" subsection).

## Oracle fixtures (you cannot make them)
